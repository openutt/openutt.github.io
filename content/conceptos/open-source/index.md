## Introducción

El término **open source** (código abierto) no significa únicamente tener acceso al código fuente. Los términos de distribución del software de código abierto deben cumplir con los siguientes criterios:

### 1\. Libre redistribución

La licencia no debe restringir a ninguna persona o entidad la venta o distribución gratuita del software como parte de una distribución de software más amplia que incluya programas provenientes de diferentes fuentes. La licencia no debe exigir el pago de regalías ni de ningún otro tipo de tarifa por dicha venta o distribución.

### 2\. Código fuente

El programa debe incluir el código fuente y debe permitir su distribución tanto en forma de código fuente como en forma compilada. Cuando alguna versión del producto no se distribuya junto con el código fuente, debe existir un medio ampliamente conocido para obtener dicho código por un costo que no exceda un gasto razonable de reproducción, preferentemente mediante descarga gratuita a través de Internet.

El código fuente debe ser la forma preferida para que un programador pueda modificar el programa. No se permite código fuente deliberadamente ofuscado. Tampoco se permiten formas intermedias, como la salida generada por un preprocesador o un traductor.

### 3\. Obras derivadas

La licencia debe permitir modificaciones y la creación de obras derivadas, así como su distribución bajo los mismos términos de la licencia del software original.

### 4\. Integridad del código fuente del autor

La licencia puede restringir la distribución del código fuente en forma modificada únicamente si permite la distribución de **archivos de parches ("patch files")** junto con el código fuente, con el propósito de modificar el programa durante el proceso de compilación.

La licencia debe permitir explícitamente la distribución del software construido a partir de código fuente modificado. Asimismo, puede exigir que las obras derivadas utilicen un nombre o número de versión diferente al del software original.

### 5\. No discriminación contra personas o grupos

La licencia no debe discriminar a ninguna persona ni grupo de personas.

### 6\. No discriminación contra áreas de actividad

La licencia no debe restringir a nadie el uso del programa en un campo específico de actividad. Por ejemplo, no puede prohibir que el programa sea utilizado en una empresa ni impedir su uso en investigaciones genéticas.

### 7\. Distribución de la licencia

Los derechos asociados al programa deben aplicarse a todas las personas a quienes el programa sea redistribuido, sin necesidad de que dichas personas acepten o ejecuten una licencia adicional.

### 8\. La licencia no debe ser específica para un producto

Los derechos asociados al programa no deben depender de que este forme parte de una distribución particular de software. Si el programa se extrae de esa distribución y se utiliza o redistribuye conforme a los términos de su licencia, todas las personas que reciban el programa redistribuido deben gozar de los mismos derechos que aquellos concedidos junto con la distribución original del software.

### 9\. La licencia no debe restringir otro software

La licencia no debe imponer restricciones sobre otro software que se distribuya junto con el software licenciado. Por ejemplo, no debe exigir que todos los demás programas distribuidos en el mismo medio sean también software de código abierto.

### 10\. La licencia debe ser neutral respecto a la tecnología

Ninguna disposición de la licencia puede depender de una tecnología específica o de un estilo particular de interfaz.
